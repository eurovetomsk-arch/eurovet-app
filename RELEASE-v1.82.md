# Мой ЕВРОВЕТ 1.82 — приёмка кассы и покрытие Vetmanager

## Объём

Релиз добавляет отдельную, append-only приёмку переходящей наличной кассы:

- ожидаемая сумма читается с сервера из последней версии предыдущего отчёта;
- фактическую сумму администратор вводит вручную;
- подписант определяется серверной сессией, а не выбранной фамилией;
- повтор, конкуренция и устаревший источник блокируются на сервере;
- исправление создаёт новую запись с причиной, не меняя старую;
- офлайн-запись остаётся неподтверждённой до серверной квитанции.

Также добавлен неизменяемый журнал покрытия Vetmanager. Экран «Контроль» больше
не может показывать «расхождений нет», если текущая версия отчёта не проверена
по счетам, выручке, платежам, кассе и ответственным каждой строки счёта.

Релиз **не меняет** `ev_reports`, зарплаты, МР-инкассации или книжный сейф. В
режиме `shadow` приёмка кассы не блокирует основной отчёт. Неполная сверка
Vetmanager всегда остаётся красной и не может быть принята как полная.

## Порядок выката

1. Убедиться, что ветка основана на актуальном GitHub `main`.
2. Выполнить свежую зашифрованную резервную копию.
3. Выполнить изолированный restore-test: `bash tests/db-shadow-drill.sh`.
4. Применить `migrations/20261113_cash_handover_shadow.sql`,
   `migrations/20261113_cash_handover_fk_indexes.sql` и
   `migrations/20261113_vetmanager_coverage_gate.sql`, затем совместимый
   `migrations/20261113_vetmanager_coverage_accepted_fix.sql` и точный ACL
   `migrations/20261113_vetmanager_coverage_gate_acl_fix.sql`. По умолчанию feature flag остаётся `off`.
5. Проверить security/performance advisors, RPC приёмки и журнал покрытия.
6. Опубликовать frontend 1.82 и убедиться, что cache key — `ev-shell-v82`.
7. Проверить production с flag=`off`: действующий отчёт, зарплата и роли не изменились.
8. Включить `shadow` отдельной короткой миграцией только после проверки frontend.
9. Наблюдать 3 полных дня и 3/3 филиала. До отдельного решения не переводить в `required`.

## Мгновенный откат

1. Применить `migrations/20261113_cash_handover_shadow_rollback.sql` — это только `mode='off'`.
2. Вернуть предыдущий frontend commit и cache key.
3. Не удалять `ev_cash_handover_events`: это неизменяемое доказательство.

## Проверка

- `node tests/release-v182.test.cjs`
- компиляция встроенного JS через `new Function(...)`
- `bash tests/db-shadow-drill.sh`

Локальный DB drill восстанавливает свежий read-only dump в одноразовый PostgreSQL и проверяет: RLS/grants, feature-off, admin+doctor multi-role, запрет doctor/assistant, head correction, idempotency, duplicate root, порог 0,01 ₽ и неизменяемость истории.

## Известный независимый блокер

Автоматическая Vetmanager-сверка после 04.11.2026 не имела исполнителя. В 1.82
этот пробел перестаёт маскироваться нулём: пока внешний read-only сборщик не
передал полное покрытие, приложение показывает красную неполноту. Временный
сборщик может работать через Codex. Постоянный AI-независимый worker требует
серверного Vetmanager credential и поддержанного массового источника
line-responsible; ключ не должен попадать в браузер, GitHub или модель.
